# Лабораторная работа № 4
## Проверка применимости данных и надёжности предсказаний модели

**Вариант:** 18
**Датасет:** 20 Newsgroups
**Количество классов:** 4
**Базовая модель:** EmbeddingBag + MLP из ЛР3

## 1. Цель работы

Разработать и исследовать валидатор применимости входных текстовых данных, позволяющий выявлять документы, для которых предсказания обученной модели могут быть ненадёжными.

Задачи работы:

1. Сформировать числовые признаки текстовых документов.
2. Реализовать обучение статистик в режимах Full и Chunk.
3. Разработать правила отклонения неподходящих документов.
4. Проверить валидатор на известных и чужеродных данных.
5. Рассчитать метрики качества и зарегистрировать эксперименты в MLflow.
6. Исследовать ограничения метода и возможные улучшения.

## 2. Исходные данные

Использован датасет 20 Newsgroups с четырьмя классами:

- `alt.atheism`;
- `talk.religion.misc`;
- `comp.graphics`;
- `sci.space`.

Разбиение данных:

| Выборка | Документов |
|---|---:|
| Train | 1624 |
| Validation | 410 |
| Test | 1353 |
| Всего | 3387 |

Для предсказаний использована замороженная модель из ЛР3.
Повторное обучение классификатора в рамках ЛР4 не выполнялось.

## 3. Архитектура исходного валидатора

Для каждого документа вычисляются шесть признаков:

1. Логарифм длины текста.
2. Доля токенов в первом частотном интервале.
3. Доля токенов во втором частотном интервале.
4. Доля токенов в третьем частотном интервале.
5. Доля токенов в четвёртом частотном интервале.
6. Доля неизвестных токенов (OOV).

Статистики распределения признаков рассчитываются только
на обучающей выборке.

Исходный валидатор отклоняет документ при выполнении
хотя бы одного условия:

- статистическое расстояние превышает порог;
- уверенность классификатора ниже порога;
- длина документа превышает допустимый предел.

Параметры сохранены в `validator_params.npz`.

## 4. Сравнение режимов Full и Chunk

Реализованы два способа расчёта статистик:

- Full — обработка всей матрицы признаков;
- Chunk — последовательная обработка блоков документов
  с обновлением статистик.

Для Chunk использован устойчивый алгоритм обновления
среднего и дисперсии.

Результаты измерений:

| Показатель | Full | Chunk |
|---|---:|---:|
| Время, с | 2.8974 | 2.8822 |
| Пиковая память tracemalloc, МиБ | 4.5323 | 1.3261 |

Максимальное расхождение средних: 4.44e-15.

Максимальное расхождение дисперсий: 4.44e-16.

**Вывод:** результаты Full и Chunk численно эквивалентны
в пределах погрешности вычислений. В данном запуске
Chunk потребовал меньше отслеживаемой Python-памяти.

Показатели памяти получены через `tracemalloc`
и не равнозначны полному потреблению оперативной памяти
процессом.

## 5. Исходный валидатор: результаты

На экспериментальном наборе из 48 искусственных
чужеродных примеров получены:

| Метрика | Значение |
|---|---:|
| Recall обнаружения чужеродных примеров | 91.67% |
| Precision отклонения | 78.57% |
| FRR на оценочной части validation | 5.85% |
| ROC-AUC | 0.9783 |

На тестовой выборке из 1353 известных документов:

| Метрика | Значение |
|---|---:|
| Отклонено | 139 |
| FRR | 10.27% |
| Accuracy классификатора без отклонения | 79.45% |
| Accuracy среди принятых документов | 82.54% |

Требование FRR <= 10% на этой выборке не выполнено.

При проверке на 200 реальных чужеродных документах
из четырёх ранее не обучавшихся категорий:

- отклонено 45 документов;
- принято 155 документов;
- Recall составил 22.50%.

**Вывод:** исходный валидатор недостаточно эффективно
обнаруживает новые тематические категории.

## 6. Негативные проверки

Проверялись следующие виды отклонений:

- тексты на чужеродные темы;
- неизвестная лексика;
- аномальная длина;
- изменение распределения токенов;
- искусственно изменённые метки классов.

Проверка изменённых меток рассматривается отдельно:
без доступа к истинной метке текстовый валидатор
не может достоверно установить факт её подмены.

Результаты сохранены в:

- `validator_negative.log`;
- `negative_preview.csv`;
- `negative_metrics_preview.json`.

## 7. Исследование тематического сходства

Для повышения качества обнаружения чужеродных текстов
исследованы два подхода на основе TF-IDF:

1. Косинусное сходство с центроидами известных классов.
2. Косинусное сходство с ближайшим обучающим документом.

TF-IDF обучался исключительно на train.

Результаты диагностики на данных разработки:

| Метод | ROC-AUC |
|---|---:|
| Центроиды классов | 0.9783 |
| Ближайший сосед | 0.9914 |

Метод ближайшего соседа выбран для дальнейшего
исследования благодаря более высокому качеству
разделения известных и чужеродных текстов.

## 8. Калибровка улучшенного валидатора

Улучшенный валидатор использует максимальное
косинусное сходство TF-IDF-вектора документа
с документами обучающей выборки.

Параметры:

- обучающих документов: 1624;
- TF-IDF-признаков: 20000;
- калибровочных документов: 205;
- проверочных документов validation: 205;
- порог сходства: 0.18492.

Результаты:

| Метрика | Значение |
|---|---:|
| FRR калибровки | 5.37% |
| FRR на второй части validation | 3.41% |

Векторизатор и обучающая матрица сохранены в:

- `topic_vectorizer.joblib`;
- `topic_train_matrix.npz`;
- `topic_guard_metadata.json`.

Повторная загрузка валидатора проверена:
результаты расчёта сходства воспроизводятся.

## 9. Проверка улучшенного валидатора

Порог был зафиксирован до проверки на новых
чужеродных категориях.

Использованы категории:

- `comp.sys.mac.hardware`;
- `rec.motorcycles`;
- `sci.electronics`;
- `rec.sport.hockey`.

Всего: 200 чужеродных документов.

Результаты:

| Метрика | Значение |
|---|---:|
| ID test | 1353 документа |
| Ложные отказы ID | 225 |
| FRR | 16.63% |
| Чужеродные документы | 200 |
| Обнаружено чужеродных | 183 |
| Принято чужеродных | 17 |
| Recall | 91.50% |
| Precision отклонения | 44.85% |
| ROC-AUC | 0.9525 |

**Требование Recall >= 90% выполнено.**

**Требование FRR <= 10% не выполнено.**

Также не выполнено строгое условие отсутствия
принятых чужеродных документов: принято 17 примеров.
Они зарегистрированы в `topic_holdout_accepted.log`.

## 10. Анализ ошибок

На validation общая FRR тематического валидатора
составила 4.39%, на test — 16.63%.

Медианное тематическое сходство:

- Validation: 0.4985;
- Test: 0.3352.

Распределение ложных отказов на test:

| Класс | Документов | Отклонено | FRR |
|---|---:|---:|---:|
| 0 | 319 | 19 | 5.96% |
| 1 | 389 | 129 | 33.16% |
| 2 | 394 | 54 | 13.71% |
| 3 | 251 | 23 | 9.16% |

Наибольшая доля ложных отказов наблюдается
для класса 1.

Результаты согласуются с гипотезой о различии
лексического и тематического состава validation
и test, но не доказывают единственную причину
этого различия.

## 11. Ограничения эксперимента

1. Порог тематического валидатора калибровался
   на ограниченной валидационной выборке.
2. На независимой тестовой части FRR оказалась
   существенно выше, чем на validation.
3. Искусственные негативные примеры не полностью
   отражают реальные чужеродные документы.
4. Часть чужеродных документов получает высокую
   уверенность исходного классификатора.
5. Результаты разных OOD-экспериментов получены
   на разных категориях и не образуют строго
   парного сравнения.
6. Некоторые выборки уже использовались
   при анализе и выборе методов. Поэтому
   не все последующие проверки можно считать
   полностью независимыми от процесса разработки.

Пороги не корректировались по итоговым значениям
FRR и Recall на тестовых данных.

## 13. Итоговые выводы

В лабораторной работе реализован валидатор
применимости текстовых данных и исследованы
несколько способов обнаружения ненадёжных входов.

Подтверждена численная эквивалентность расчёта
статистик в режимах Full и Chunk.

Исходный валидатор показал недостаточное качество
обнаружения реальных чужеродных тематик:
Recall 22.50%.

Добавление тематического анализа TF-IDF
с ближайшим соседом повысило Recall до 91.50%
на другом наборе чужеродных категорий.

При этом FRR на тестовой выборке составила 16.63%,
поэтому совокупность целевых критериев
не достигнута.

Эксперимент показал необходимость учитывать
не только способность обнаруживать неизвестные
темы, но и устойчивость порогового решения
к различиям между обучающими и тестовыми данными.

Перспективные направления дальнейшей работы:
увеличение калибровочной выборки,
исследование поклассовых порогов,
применение семантических эмбеддингов
и повторная оценка на новых отложенных данных.

### Восстановление TF-IDF-матрицы

Файл `topic_train_matrix.npz` не включён в Git,
поскольку превышает ограничение размера файлов.

Для его восстановления необходимы исходные данные
20 Newsgroups и команда:

```bash
python -m src.lab4.topic_guard
```

Команда повторно обучает TF-IDF на train, калибрует
порог по validation и сохраняет матрицу. Для
воспроизводимости необходимы исходные данные,
фиксированный seed и версии зависимостей.
